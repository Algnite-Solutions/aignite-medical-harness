# Spark 运行环境只读审计

日期：2026-10-23。对应阶段一，补充首次 NAS 审计。登录凭证及主机地址不入库。

## 已核验

- SSH 可连通；Linux aarch64，系统 Python 3.12.3。
- 当前审计机器直接访问 Spark 模型端口成功，`GET /health` 与 `GET /v1/models` 均为 HTTP200；Spark 本机访问也成功。未发起推理请求。
- 模型目录返回 `qwen3.6`、`stgr-sft-r16`。这些是运行别名，不构成不可变权重身份。
- Docker 中存在运行中的 vLLM 模型容器，映射端口8000；Docker 和 Ollama 具有运行中的 systemd 服务。
- 现有容器还包括 Web UI、搜索和管理组件。这些组件不能直接算作 AMA 远端工具服务或其验收结果。
- 模型端口 `/v1/info` 返回404；尚未发现符合拟议 AMA 工具协议的服务，不能以模型接口代替工具接口。
- 系统 Python 的 venv、Pillow 可用；pydantic、pyarrow、vllm 不在系统 Python 中。vLLM 在容器运行，不需要安装到系统 Python。
- Spark 可列出 NAS 处理数据目录，与本机 NAS 目录名相符；这只证明目录可见，不证明两端文件字节一致。固定集哈希验证目前是在本机挂载上执行。

## 尚未核验或受阻

- 连接账号无法读取另一实验账号的 home，返回 PermissionError。当前可读 home 和限定 NAS 数据目录内的深度受限搜索未找到 benchmark.json；不能声称原 open100 不存在。
- MIMIC-CDM 原 open100 interactive cohort 及四组各25例锁仍需定位，或由原实验账户提供可读路径。
- 未检查容器环境变量或模型认证凭证；接口探测成功不代表认证/网络隔离已经符合部署要求。
- 未确认不可变模型版本、LoRA 权重摘要、容量、依赖锁、候选工具服务端口及服务账户。
- mini 的专用 runner 注册、隔离策略及 GitHub 权限仍待核验；当前机器网络连通不等于 runner 账户具备相同访问权限。

## 对部署决策的影响

保留现有模型容器，由部署侧单独维护；工具服务采用独立版本和生命周期。现有 Docker 运行条件已经存在，因此阶段二工具部署需结合现有 compose 运维方式，再确认 wheel/venv 默认方案与容器方案的最终选择。第一版文档中的 wheel 推送方案是实施提案，不是已验证部署。

服务上线前必须补齐版本化 info、独立病例会话、图像释放、调用状态、超时及回收契约；现有搜索服务不自动获得验收通过状态。

本轮只执行系统/目录/容器元数据查询、模块可用性检查及 HTTP GET。未安装远端依赖，未重启或修改服务，未读取凭证文件，未生成数据锁，未运行 ama run 或 ama eval。
